## Healthy Home dashboard — Leads tab fix

Boss reported the Leads tab wasn't loading. The `/api/canvassing/leads` endpoint was returning 500.

### Root causes (two issues stacked)

1. **Missing `hh_lead_meta` table** — schema in code defined it (`lib/db/src/schema/lead-meta.ts`) but it had never been created in Supabase. The leads list query does a `leftJoin` on it, so the whole query blew up.
2. **Missing columns on `leads` table** — schema in code (`lib/db/src/schema/canvassing.ts`) had ~19 newer columns (property lookup state, imagery estimation, requested_timeline, exact_service_requested, gutter_linear_feet, property_stories, etc.) that didn't exist in the actual Supabase `leads` table. Drizzle's `.select({lead: leadsTable})` does a full SELECT of all schema columns, so any missing column = 500.

### What we ran in Supabase SQL Editor

1. Created `hh_lead_meta` table with FK to `leads(id)` ON DELETE CASCADE, plus indexes on `lead_id` and `is_deleted`.
2. Initially enabled RLS with `auth.role() = 'authenticated'` policies — wrong approach for our use case because the backend connects via direct postgres URL (not via Supabase PostgREST). RLS then disabled. Postgres superuser typically bypasses RLS but we left it disabled here for now since the API layer (DASHBOARD_PASSWORD cookie / tech bearer) is what actually gates access.
3. Added all 19 missing columns to `leads` via `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`.

Migration file saved at: `hh-backend-fresh/scripts/migrations/2026-05-01-add-lead-meta-table.sql`

### Verified

`GET /api/canvassing/leads` now returns 200 with actual lead data. Leads tab should load for Boss.

### Follow-up items — both done same session

- ✅ **Re-enabled RLS on `hh_lead_meta`** with explicit `postgres, service_role` ALL policy. Frontend anon/authenticated keys can't reach it; backend direct postgres connection has full access.
- ✅ **Schema drift audit** — built a reusable script at `hh-backend-fresh/lib/db/scripts/schema-drift-audit.ts`. It imports all schema files, queries `information_schema.columns`, diffs them, and emits a SQL migration file. **First run found 6 missing tables and 28 missing columns** — affecting Campaigns, Job Photos, Tech Clock, Tech Locations features (all would 500 on access). Migration applied via `scripts/migrations/2026-05-01-schema-drift-fix.sql`. Re-audit confirmed ZERO drift.
- Run the audit before every deploy: `cd lib/db && SUPABASE_DATABASE_URL=... pnpm tsx scripts/schema-drift-audit.ts` (note: tsx may need to be invoked via `node node_modules/.pnpm/tsx@*/node_modules/tsx/dist/cli.mjs` if pnpm can't resolve it directly — happened locally, may not on Replit).

### Still open

- **Migration discipline** — there's `lib/db/migrations/` and `scripts/migrations/` but Drizzle's migration generator isn't being used consistently. Should formalize: every schema change requires a SQL migration file checked in, and the audit script runs on every deploy as a sanity check.
- The `DASHBOARD_PASSWORD` may not be set on Replit — my unauthenticated requests reached the leads handler directly. Worth confirming and setting if not. (Backend currently relies on "who knows the URL" for auth, which is weak.)
- The audit script's auto-generated DDL needs manual cleanup for: PRIMARY KEY detection, `defaultNow()` → `DEFAULT NOW()`, `gen_random_uuid()`, and array defaults (it emitted `'[]'::jsonb` for text[] cols). I cleaned the migration by hand. Worth improving the script next time it's used.

## 21:13-21:25 EDT — HH backend hotfix: 'Catch up on FB' Unauthorized + toast X invisible

Boss hit 'Catch up on FB' on the live HH dashboard, got 'Error Unauthorized'. Also flagged that error toasts had no X close button.

**Root causes:**
1. **Auth bug**: /api/facebook/* endpoints use a separate isAdmin() helper that didn't match the page-level middleware. When DASHBOARD_PASSWORD is unset (which it is on Replit currently), the page middleware lets you in but isAdmin returned false (because Boolean(cookie='') is false). 401 every time.
2. **Toast X bug**: ToastClose component had 'opacity-0 group-hover:opacity-100' — the X is invisible until you HOVER the toast, which doesn't work on touch devices. Boss couldn't dismiss errors.

**Fixes shipped (Replit commit 00a7586, awaits Publish):**
- isAdmin returns true when DASHBOARD_PASSWORD is unset, matching app.ts page-level behavior. Open mode is consistent across both layers.
- ToastClose: always visible, larger tap target (p-1.5 instead of p-1), better hover bg, toast container bumped to pr-12 for room. Also affects success toasts.

**Still open:**
- Boss should set DASHBOARD_PASSWORD on Replit secrets eventually (currently anyone with the URL can use the dashboard). Once set, isAdmin's pwd-required path takes over correctly.
- These fixes need a Publish to go live.
